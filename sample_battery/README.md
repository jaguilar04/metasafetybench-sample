# Sample battery

A small, reproducible sample drawn from the full dataset: 200 questions
across all 8 benchmarks, answered by 10 hand-picked models, with their
binary judged outcome.

Generated by `build_sample_battery.py`. The `battery/` folder in this repo
is never used as a source (it is gitignored and treated as if it did not
exist) — everything here is built directly from `matrices/`, `responses/`,
and `scores/`.

## Build

From the repository root:

```bash
python3 sample_battery/build_sample_battery.py
```

This is deterministic (fixed random seed), so re-running it regenerates
the same `items.jsonl` and `responses.jsonl`.

## What's selected

**200 questions**, allocated proportionally across the 8 benchmarks
according to each benchmark's size in `matrices/manifest.json`
(largest-remainder rounding, so the counts sum exactly to 200):

| Dataset | Items |
| --- | --- |
| orbench_hard | 50 |
| donotanswer | 36 |
| truthfulqa | 31 |
| ahb | 27 |
| advbench | 20 |
| sorrybench | 17 |
| harmbench | 11 |
| health_orsc | 8 |

Within each benchmark, items are sampled uniformly at random (seed 42)
from those that all 10 selected models actually have a judged score for,
so the resulting grid has no missing cells.

**10 models**, picked for diversity rather than for scoring highest:

| Model | Why it's included |
| --- | --- |
| `openai/gpt-5-mini` | frontier closed model |
| `anthropic/claude-sonnet-4.5` | frontier closed model |
| `google/gemini-2.5-pro` | frontier closed model |
| `deepseek/deepseek-v3.2` | frontier open-weight model |
| `qwen/qwen3.5-plus-20260420` | frontier open-weight model, different vendor |
| `z-ai/glm-4.7` | open-weight model, different vendor |
| `x-ai/grok-4.3` | closed model, different vendor |
| `mistralai/mistral-large-2512` | closed model, different vendor |
| `meta-llama/llama-3.2-1b-instruct` | small/cheap model |
| `openai/gpt-3.5-turbo` | older baseline, for a sense of progress over time |

For HarmBench specifically, scores come from the LLM judge
(`haiku-anthropic_claude-haiku-4.5`), not the `refusal-strings` judge that
is also available in `scores/harmbench/`.

## Output files

### `items.jsonl` — 200 lines, one per question

| Field | Meaning |
| --- | --- |
| `item_id` | Original item identifier (also encodes the dataset prefix, e.g. `ahb_0139`). |
| `dataset` | Which of the 8 benchmarks this question is from. |
| `prompt` | The question text, taken from `responses/<dataset>/<model>.jsonl` (prompts are identical across models for the same item). |

### `responses.jsonl` — 2000 lines, one per (question, model) pair

| Field | Meaning |
| --- | --- |
| `item_id` | Matches an `item_id` in `items.jsonl`. |
| `model` | One of the 10 selected models. |
| `score` | Binary judged outcome for this model's response to this item (`0.0`/`1.0`), taken from `scores/<dataset>/<model>.jsonl`. |
| `label` | The judge's raw label before it was collapsed to a binary score (e.g. `"refused"`/`"complied"`, `"yes"`/`"no"`, or, for Do-Not-Answer, a 6-way action category `"0"`–`"5"`). |

Each item has exactly 10 responses (one per model), so
`responses.jsonl` has `200 * 10 = 2000` lines.

## Where each field comes from

```
matrices/manifest.json         -> per-benchmark item counts (for the 200-item split)
matrices/matrix_<dataset>.parquet -> which (model, item) pairs have a judged score
responses/<dataset>/<model>.jsonl -> item_id, prompt
scores/<dataset>/<model>[.judge].jsonl -> item_id, model, score, label
```

`battery/` is intentionally excluded from this pipeline.
